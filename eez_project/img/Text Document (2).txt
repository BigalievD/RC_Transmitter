схему подключения железок можно?

Да. И здесь уже лучше сделать реальную электрическую схему подключения, а не просто блок-схему.

Я сверил распиновку именно твоей Waveshare ESP32-P4-WIFI6-Touch-LCD-4.3 с документацией Waveshare и отдельно проверил ADS1115 и E22. У платы наружу выведен 40-pin GPIO-разъём, а штатная I²C-шина использует GPIO7 = SDA и GPIO8 = SCL.

1. Общая схема пульта

Я бы строил пульт так:

                         ┌──────────────────────────────┐
                         │   ESP32-P4-WIFI6-Touch-LCD  │
                         │                              │
                         │        ESP32-P4              │
                         │                              │
                         │  GPIO7  ───── SDA            │
                         │  GPIO8  ───── SCL            │
                         │                              │
                         │  UART TX ────────┐          │
                         │  UART RX ────────┤          │
                         │  DIO1   ◄────────┤          │
                         │  TXEN   ─────────┤          │
                         │  RXEN   ─────────┤          │
                         └──────────┬────────┴──────────┘
                                    │
                 ┌──────────────────┴──────────────────┐
                 │                                     │
              I²C BUS                               UART
                 │                                     │
       ┌─────────┼─────────┐                           │
       │         │         │                           │
    ADS1115   ADS1115   ADS1115                  E22-900N30S
       │         │         │                           │
       │         │         │                           │
       ▼         ▼         ▼                           ▼
     СТИКИ    СЛАЙДЕРЫ  РЕЗЕРВ                  АНТЕННА 900 MHz

То есть все три ADS1115 сидят на одной I²C-шине.

Это очень удобно.

2. I²C-шина ADS1115

У ESP32-P4:

GPIO7 → SDA
GPIO8 → SCL

Именно такая распиновка указана Waveshare для этой платы.

Подключение:

ESP32-P4                    ADS1115 #1
────────                    ──────────
3V3       ────────────────► VDD
GND       ────────────────► GND
GPIO7     ────────────────► SDA
GPIO8     ────────────────► SCL

И параллельно:

GPIO7 ───── SDA ───── SDA ───── SDA
GPIO8 ───── SCL ───── SCL ───── SCL
             │         │         │
          ADS1115    ADS1115   ADS1115

Важно: SDA и SCL не нужно делать отдельными линиями для каждого ADS1115.

Все три работают на одной шине.

3. Адреса ADS1115

Здесь есть очень удобное решение.

У ADS1115 четыре возможных I²C-адреса:

ADDR	Адрес
GND	0x48
VDD	0x49
SDA	0x4A
SCL	0x4B

Это прямо указано в документации TI.

Поэтому можно сделать:

ADS1115 #1
ADDR → GND
I²C = 0x48


ADS1115 #2
ADDR → 3V3
I²C = 0x49


ADS1115 #3
ADDR → SDA
I²C = 0x4A

Получаем:

                   I²C BUS


GPIO7 SDA ─────────┬──────────────┬──────────────┐
                   │              │              │
                 ADS #1         ADS #2         ADS #3
                 0x48           0x49           0x4A
                   │              │              │
GPIO8 SCL ─────────┴──────────────┴──────────────┘

Это намного лучше, чем городить I²C-мультиплексор.

4. Что подключить к каждому ADS1115

Я бы распределил каналы следующим образом.

ADS1115 №1 — левый стик
AIN0 → AIL
AIN1 → ELE
AIN2 → THR
AIN3 → RUD

То есть:

              ADS1115 #1
             ┌───────────┐
AIL ─────────► AIN0      │
ELE ─────────► AIN1      │
THR ─────────► AIN2      │
RUD ─────────► AIN3      │
             └───────────┘
5. ADS1115 №2 — дополнительные оси стиков

У JH-D400R4 есть дополнительные оси.

Например:

AIN0 → Stick L Z
AIN1 → Stick R Z
AIN2 → дополнительный потенциометр
AIN3 → дополнительный потенциометр
6. ADS1115 №3 — боковые слайдеры

Например:

AIN0 → Left Slider
AIN1 → Right Slider
AIN2 → свободный
AIN3 → свободный

Получаем запас ещё на два аналоговых источника.

Это хороший вариант, потому что потом можно добавить:

потенциометр;
отдельный регулятор;
датчик;
дополнительный аналоговый орган управления.
7. Подключение JH-D400R4

Каждая аналоговая ось фактически является потенциометром.

Типовая схема:

             3.3V
              │
              │
          ┌───┴───┐
          │       │
          │ POT   │
          │       │
          └───┬───┘
              │
              └────────────► ADS1115 AINx
              │
          ┌───┴───┐
          │       │
          └───┬───┘
              │
             GND

То есть:

3V3 ───── верх потенциометра
GND ───── низ потенциометра
WIPER ─── ADS1115 AIN

Но перед окончательной пайкой именно твоих JH-D400R4 я бы прозвонил распиновку конкретного экземпляра мультиметром, потому что у продавцов встречаются разные варианты разводки одинаково обозначенных стиков.

8. Кнопка сверху стика

Кнопки JH-D400R4 — это уже цифровые входы.

Например:

GPIOx ───────────── кнопка ───────── GND

А в программе:

pinMode(GPIOx, INPUT_PULLUP);

Получаем:

отпущена → HIGH
нажата   → LOW

Это касается и остальных механических кнопок/переключателей.

9. Переключатели

Например SA:

3V3
 │
 ├──── Switch position 1
 │
 ├──── Switch position 2
 │
 └──── Switch position 3

Но конкретную схему зависит от типа переключателя.

Для обычного двухпозиционного:

GPIO ───── SWITCH ───── GND

Для трёхпозиционного удобно использовать два GPIO:

             ┌── GPIO_A
             │
       ┌─────┤
       │     │
       │   SWITCH
       │     │
       └─────┤
             │
           GPIO_B

и определять:

00 → положение 1
01 → положение 2
10 → положение 3
10. E22-900N30S

Вот здесь есть важный момент, особенно учитывая нашу предыдущую тему с TXEN/RXEN.

E22-900M30S использует отдельное управление RF switch. Для подобных E22 документация указывает использование DIO2 для управления передающей частью RF switch; также существуют варианты с отдельными TXEN и RXEN.

Я бы для твоего проекта сделал полностью управляемую схему, а не оставлял RXEN висеть.

То есть:

ESP32-P4                     E22-900N30S


UART_TX ───────────────────► RXD
UART_RX ◄─────────────────── TXD


GPIO_RADIO_DIO1 ◄─────────── DIO1


GPIO_RADIO_TXEN ───────────► TXEN
GPIO_RADIO_RXEN ───────────► RXEN


3V3/5V ─────────────────────► VCC
GND ────────────────────────► GND


ANT ────────────────────────► 900 MHz antenna

При этом:

TX:
TXEN = HIGH
RXEN = LOW


RX:
TXEN = LOW
RXEN = HIGH

Именно такой принцип управления RF switch используется для модулей с отдельными RXEN/TXEN.

11. DIO2

В нашем случае я бы не использовал DIO2 как обычный GPIO, пока мы не определимся с конкретной схемой RF switch.

Есть два нормальных варианта.

Вариант А — отдельное управление
TXEN ← GPIO
RXEN ← GPIO
DIO1 ← GPIO
DIO2 ← GPIO / NC

Это самый гибкий вариант.

Вариант Б — DIO2 управляет TXEN

Документация E22 указывает возможность:

DIO2 → TXEN

для управления RF switch.

Тогда:

DIO2 ───────── TXEN


RXEN ───────── GPIO ESP32

Но для нашей системы я предпочёл бы вариант А, поскольку у нас достаточно GPIO и он проще для отладки.

12. UART E22

Подключение:

ESP32 TX
   │
   └──────────────► E22 RXD


ESP32 RX
   ▲
   │
   └────────────── E22 TXD

Обязательно:

GND ESP32 ─────── GND E22

UART работает по перекрёстной схеме:

TX → RX
RX ← TX

а не:

TX → TX
RX → RX
13. Питание E22

Вот это особенно важно.

E22-900N30S — мощный радиомодуль.

Его питание нельзя проектировать как обычное маломощное периферийное устройство.

Я бы сделал отдельную силовую ветку:

АККУМУЛЯТОР
     │
     ▼
DC/DC
     │
     ├──────────────► ESP32-P4
     │
     └──► отдельный RF regulator
                    │
                    ▼
                 E22

При этом:

GND аккумулятора
      │
      ├── GND ESP32
      ├── GND ADS1115
      └── GND E22

Но точное напряжение питания надо брать именно из даташита твоей ревизии E22-900N30S, а не автоматически считать его 3,3 В только потому, что логика микроконтроллера 3,3 В.

14. Питание ADS1115

ADS1115 можно запитать от 3,3 В:

ESP32 3V3
   │
   ├──── ADS #1 VDD
   ├──── ADS #2 VDD
   └──── ADS #3 VDD

И:

ESP32 GND
   │
   ├──── ADS #1 GND
   ├──── ADS #2 GND
   └──── ADS #3 GND

При этом аналоговые органы управления тоже желательно питать от того же стабильного 3,3 В, чтобы их измерение было относительно стабильного опорного напряжения.

15. Важный момент с ADS1115

Я бы не использовал для стиков дифференциальный режим.

Нам нужен обычный single-ended:

AIN0 → напряжение стика
AIN1 → напряжение стика
AIN2 → напряжение стика
AIN3 → напряжение стика

То есть каждый орган управления измеряется относительно GND.

16. Общая схема питания пульта

Я бы сделал её примерно так:

17. Что я бы сделал с GPIO

Здесь есть один нюанс: нельзя просто взять любые GPIO из 40-pin разъёма.

На ESP32-P4-WIFI6-Touch-LCD-4.3 часть GPIO уже используется самой платой — дисплеем, аудио, TF, ESP32-C6, USB и другими периферийными узлами. Схема платы показывает, в частности, внутренние подключения GPIO, поэтому свободные GPIO надо выбирать после составления полной таблицы.

Поэтому я предлагаю распределить их примерно так:

Функция	Интерфейс	GPIO
ADS1115 SDA	I²C	GPIO7
ADS1115 SCL	I²C	GPIO8
E22 TX	UART	свободный GPIO
E22 RX	UART	свободный GPIO
E22 DIO1	IRQ	свободный GPIO
E22 TXEN	GPIO	свободный GPIO
E22 RXEN	GPIO	свободный GPIO
Stick L button	GPIO	свободный
Stick R button	GPIO	свободный
SA	GPIO	свободный
SB	GPIO	свободный
SC	GPIO	свободный
дополнительные кнопки	GPIO	свободные

GPIO7/8 я бы однозначно оставил под I²C. Они штатно предназначены для этой шины на данной плате.

И ещё один важный момент

Для полной принципиальной схемы, включая конкретные GPIO, питание E22, TXEN/RXEN/DIO1, все кнопки и переключатели, я бы следующим шагом сделал таблицу "компонент → пин → GPIO → питание → назначение", а затем уже по ней можно разводить PCB.

Особенно важно сначала зафиксировать GPIO E22 и цифровых органов управления: у Waveshare часть GPIO уже занята внутренними функциями платы.

Также я бы отдельно заложил аппаратный power monitor пульта и измерение напряжения аккумулятора — тогда экран 7.6 V, предупреждение о низком заряде и автоматический shutdown будут не просто элементами UI, а реально связанными с железом функциями.
